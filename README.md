# 수영 기록 대시보드

아이폰 단축어가 매일 밤 애플 건강앱의 수영 기록을 이 서버로 보내면, SQLite에 쌓고
최근 1년 추이·향상도·규칙 기반 조언을 웹 대시보드로 보여준다. 혼자 쓰는 개인용 도구.

```
main.py            FastAPI 앱 전체 (라우트 + 스키마 + 집계 + 조언 규칙)
static/index.html  대시보드
test_main.py       테스트 3개
swim.db            첫 실행 시 자동 생성
```

## 1. 실행 (윈도우 PowerShell)

```powershell
cd D:\claude\fitness_app
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install fastapi uvicorn pytest

$env:SWIM_TOKEN = "아무거나-길고-어려운-문자열"     # 이걸 단축어 헤더에 그대로 넣는다
.\.venv\Scripts\uvicorn.exe main:app --host 0.0.0.0 --port 8000
```

브라우저에서 http://localhost:8000 접속.

`SWIM_TOKEN`을 설정하지 않으면 POST는 전부 401이다 (기본값이 빈 문자열이라 안전하게 잠긴다).
매번 입력하기 싫으면 한 번만:

```powershell
[Environment]::SetEnvironmentVariable("SWIM_TOKEN", "아무거나-길고-어려운-문자열", "User")
```
(새 PowerShell 창부터 적용된다.)

테스트:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## 2. 아이폰에서 PC로 접속하기 (cloudflared)

집 공유기 포트포워딩 없이 외부에서 접속하는 가장 짧은 방법. 서버를 켠 채로 다른 창에서:

```powershell
cloudflared tunnel --url http://localhost:8000
```

(`winget install Cloudflare.cloudflared`로 설치. 로그인·계정 없이 무료로 쓸 수 있다.)

출력되는 `https://xxxx-yyyy.trycloudflare.com` 주소를 단축어의 URL에 넣는다.

> **주의: 이 무료 주소는 cloudflared를 껐다 켤 때마다 바뀐다.** 바뀌면 단축어의 URL도 고쳐야 한다.
> 고정 주소가 필요하면 Cloudflare 계정을 만들고 named tunnel을 쓰면 되지만, 개인용이라면 그냥
> 주소가 바뀔 때 단축어를 고치는 쪽이 간단하다.

**PC가 꺼져 있으면?** 그날 전송은 그냥 실패한다. 하지만 단축어가 매번 최근 400일치를 통째로 다시
보내고 서버는 `start`를 키로 UPSERT하므로, 다음에 한 번만 성공하면 빠진 날짜가 전부 자동으로
복구된다. 며칠 놓쳐도 신경 쓸 필요 없다.

## 3. 아이폰 단축어 설치

서버가 완성된 단축어 파일을 만들어서 내려준다. 손으로 액션을 조립하지 않아도 된다.

### 1) 아이폰에서 "신뢰할 수 없는 단축어" 허용

**설정 → 단축어 → "신뢰할 수 없는 단축어 허용" 켜기**

이 항목이 안 보이면, 단축어 앱에서 아무 단축어나 한 번 실행한 뒤 다시 들어가면 나타난다.
(애플이 서명 안 된 단축어를 기본적으로 막아두기 때문이다. 내가 만든 파일은 서명이 없다.)

### 2) 파일 받기

아이폰 사파리로 아래 주소를 연다:

```
https://<터널주소>.trycloudflare.com/shortcut
```

대시보드를 아이폰으로 열었다면 화면 위의 **"📲 아이폰 단축어 받기"** 링크를 눌러도 된다.

**다운로드에 사용한 주소와 현재 토큰이 파일 안에 자동으로 박힌다.** 나중에 터널 주소가
바뀌면 이 주소로 다시 받기만 하면 된다 — 단축어를 고칠 필요가 없다.

### 3) 가져오기

파일 앱 → 다운로드 폴더 → 받은 `swim.shortcut` 을 탭 → **단축어 추가**.
단축어 앱에 "수영 기록 전송"이 생긴다.

### 4) 테스트

단축어를 열고 **재생 버튼(▶)** 을 누른다. 건강 데이터 접근 권한을 처음 한 번 물어보므로 허용한다.
마지막에 이런 응답이 뜨면 성공이다:

```
{"received":42,"inserted":42,"updated":0,"skipped":0}
```

- 한 번 더 실행하면 `inserted:0, updated:42`. 행은 늘지 않는다 (멱등).
- `skipped`가 0이 아니면 날짜 포맷 문제다 (아래 참고).
- 브라우저에서 대시보드를 새로고침하면 차트가 채워져 있어야 한다.

### 5) 매일 자동 실행 연결

**자동화 탭 → + → 시간대 → 매일 오후 10:00 → 즉시 실행**
(“실행 전 확인”을 꺼야 알림 없이 자동으로 돈다.)
동작으로 `단축어 실행`을 고르고 "수영 기록 전송"을 지정한다.

### 단축어에 들어있는 것

```
1. 운동 찾기              (수영, 최신순 1000개)
2. 각 항목 반복
     └ 사전 만들기        (start / end / duration_sec / distance_m)
3. URL 콘텐츠 가져오기    (POST, 헤더 X-Token, 본문 = 반복 결과)
```

`start`와 `end`에는 **ISO 8601 + 시간 포함** 포맷이 지정되어 있다. 이게 이 단축어에서 가장
중요한 설정이다 — 없으면 `2026년 7월 28일 오전 6:12` 같은 한국어 날짜가 나가고 서버가
그 기록을 버린다(`skipped` 증가).

## 3-1. 단축어 파일이 안 열릴 때 — 손으로 만들기 (액션 3개)

iOS 버전에 따라 서명 없는 단축어 파일을 거부할 수 있다. 그럴 땐 아래대로 직접 만든다.
5분이면 된다. 빈 목록을 만들거나 변수를 따로 설정할 필요는 **없다** —
"각 항목 반복" 액션이 결과를 자동으로 `반복 결과`라는 목록으로 내놓기 때문이다.

```
1. 운동 찾기              (수영, 최근 400일)
2. 각 항목 반복
     └ 사전 만들기        (줄 3개: start / duration_sec / distance_m)
3. URL 콘텐츠 가져오기    (POST, 본문에 "반복 결과")
```

### 먼저: 손으로 되는지부터 만든다

자동화로 바로 만들지 말고 **단축어 탭 → + (새 단축어)** 로 만들어서 재생 버튼으로 테스트한다.
잘 돌면 그때 자동화에 연결한다. 자동화 안에서는 실행 결과를 볼 수 없어서 디버깅이 안 된다.

### 액션 1 — 운동 찾기

검색창에 `운동 찾기` 입력해서 추가한다. (영문이면 Find Workouts)

- 필터 추가: `운동 유형` `는` `수영`
- 필터 추가: `시작일` `가 다음 이내` `400` `일`
- 정렬·개수 제한은 건드리지 않는다 (전부 보내야 빠진 날이 자동 복구된다)

### 액션 2 — 각 항목 반복 + 사전 만들기

`각 항목 반복`을 추가하면 입력이 자동으로 1번 결과가 된다. 그 **안에** `사전`을 추가하고
아래 3줄만 넣는다. 값 칸을 탭한 뒤 변수 선택 → `반복 항목` → 세부 정보를 고른다.

| 키 | 타입 | 값 |
|---|---|---|
| `start` | 텍스트 | 반복 항목 → **시작 날짜** |
| `duration_sec` | 숫자 | 반복 항목 → **지속 시간** |
| `distance_m` | 숫자 | 반복 항목 → **거리** |

> ### ⚠️ 여기가 유일하게 까다로운 부분: 날짜 포맷
>
> `start` 값에 넣은 **시작 날짜 변수를 한 번 탭**하면 옵션이 열린다.
> 거기서 **날짜 포맷 → ISO 8601**, **시간 포함 → 켬** 으로 바꾼다.
>
> 이걸 안 하면 `2026년 7월 28일 오전 6:12` 같은 한국어 날짜가 전송되고,
> 서버는 그 기록을 **조용히 버린다**. 응답의 `skipped`가 0이 아니면 십중팔구 이것이다.

나머지 필드(`end`, `energy_kcal`, `type`, `avg_hr`, `location`)는 넣어도 되지만 **대시보드에서
쓰지 않는다.** 익숙해진 뒤에 추가해도 늦지 않다. `duration_sec` 대신 `end`를 넣으면 서버가
`start`와 `end`로 시간을 직접 계산한다.

### 액션 3 — URL 콘텐츠 가져오기

반복 **바깥**에 추가한다.

- URL: `https://xxxx.trycloudflare.com/api/workouts`
- `▶︎ 더 보기` 를 펼쳐서:
  - 방식: `POST`
  - 헤더: `X-Token` = 2번 항목에서 정한 `SWIM_TOKEN` 값
  - 본문 요청: `JSON` → 아래 `파일` 칸에 변수 **`반복 결과`** 를 넣는다

확인 방법과 자동화 연결은 위 3번의 4)·5)와 같다.

## 4. curl로 먼저 테스트

단축어를 만들기 전에 서버가 잘 도는지 확인:

```powershell
curl.exe -X POST http://localhost:8000/api/workouts `
  -H "Content-Type: application/json" `
  -H "X-Token: $env:SWIM_TOKEN" `
  -d '[{\"start\":\"2026-07-28T06:12:00+09:00\",\"end\":\"2026-07-28T06:52:00+09:00\",\"duration_sec\":2400,\"distance_m\":1500,\"energy_kcal\":420,\"type\":\"Swimming\",\"avg_hr\":132,\"location\":\"pool\"}]'
```

```
{"received":1,"inserted":1,"updated":0,"skipped":0}
```

같은 명령을 한 번 더 실행하면 `{"received":1,"inserted":0,"updated":1,"skipped":0}` — 행은 늘지 않는다.
토큰을 틀리면 401이 온다.

통계 확인:

```powershell
curl.exe "http://localhost:8000/api/stats?days=365"
```

## API 요약

| 엔드포인트 | 설명 |
|---|---|
| `POST /api/workouts` | 운동 객체 배열. 헤더 `X-Token` 필요. `start` 기준 UPSERT (멱등). |
| | 응답 `{"received","inserted","updated","skipped"}`. `skipped`는 `start`가 없거나 ISO 8601이 아니라 버린 개수. |
| `GET /api/stats?days=365` | 요약·월별·세션별·향상도·조언을 한 번에 반환 |
| `GET /` | 대시보드 |

- 모든 시각은 UTC로 정규화해 저장한다. `+09:00`과 `Z` 표기가 섞여도 같은 운동은 한 행이다.
- 100m 페이스(초) = `duration_sec / distance_m * 100`. 거리가 없거나 0이면 페이스 계산에서 뺀다.
- 향상도 = 이전 90일 평균 페이스 − 최근 90일 평균 페이스. 양수면 빨라진 것.
